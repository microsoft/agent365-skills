SIDE
NOTE

Sidecar approach for unsupported languages future

Today Agent 365 ships first-party SDKs only for C# / Python / TypeScript. When the user picks Other in Phase 5 (e.g. Go, Java, Rust, Ruby), the agent runs as the workload and a thin A365 sidecar hosts the SDK surface alongside it — exposing local HTTP endpoints for messaging, auth, observability, and MCP tool registration. The user’s code talks to the sidecar over loopback; the sidecar speaks the official A365 protocol outbound.

(Go / Java / Rust…)
⇄

(SDK shim, localhost)
⇄
Agent 365
Teams · WorkIQ · Observability

Until the sidecar lands, languageIsCustom = true is a best-effort scaffold using the Bot Framework Activity protocol directly on /api/messages with no language-specific reference doc.
